# ops: 週次運用の土台

Claude Codeが週1回、実データに基づく記事を書いて公開し、公開を外部から確認する仕組みの部品です。

| ファイル | 役割 |
|---|---|
| `collect_metrics.py` | Zenn・Gumroadの指標を集め、`ledger/` に保存(認証情報は環境変数から名前で読む) |
| `verify_publish.py` | 記事の公開URLが実際に200を返すかを確認(終了コード0=確認できた) |
| `WEEKLY_PROMPT.md` | 定期実行(Routines等)に渡す、自己完結の指示書とガードレール |
| `ledger/` | 指標のスナップショットと、運用台帳(`LEDGER.md`) |

## 失敗から学んだこと
- 公開実験(dev.to)では「終了コード0でも実は未完了」が最大の落とし穴だった。完了は**外部から確認**する
- 第3回の記事は、pushしたのにZennで公開されなかった。**原因は未確定**。候補は ①タイトル・本文に `$`(Zennは数式記法として解釈する)が9個あった ②Zennの投稿数の制限やデプロイの待ち行列(その日の3本目だった。デプロイは1回に1〜2件ずつ古い順に処理される、という報告がある)。両方に備えて、`$` を除去し、1日の公開数を抑える。この失敗は `verify_publish.py` で検出できた
- 公開の確認は、公開API(`https://zenn.dev/api/articles?username=ryu7865`)の件数と、ローカルの記事数の差(=待ち件数)でも分かる
- 認証情報は、コードや記事に書かない
